Volumes that may break if they are moved

Some volumes carry something that can fail after a move, for example an old Windows server, or a guest with no agent installed. OpenMove does not move these until two different people have checked them. OpenMove can only read hints (image properties, instance data, names). It cannot look inside a guest. A volume with no hint is not proven safe. Mark any volume you know is a risk.

Progress

What do the stages and the approvals mean?

The stages of a volume

Waiting to start
The volume is chosen but has no free place yet. At most the number set under "Volumes at once" are worked on together; the next one starts the moment a place is free.
Being copied and checked
OpenMove prepares the volume on the new storage, copies the data and compares it with the original, more than once. The original is not changed.
Being switched
The short moment when the volume is pointed at the new storage. It starts only after the approvals below and your release.
Switched, being verified
The volume now lives on the new storage. A second person confirms it works (the third approval).
In the safety period
The volume works on the new storage and the old copy is kept for a number of days (7 by default) so that you can go back. Nothing is needed from you. It does not take one of the places.
Finished
The safety period is over. The volume is done.
Stopped or put back
Something was wrong, or a person stopped it. The volume is back where it was, with its data intact.

The three approvals by a second person

1. The copy is correct (also called G2)
The copy on the new storage was built and compared with the original: every image, every snapshot, in the right order.
2. Ready to switch (also called G3)
The new record exists, the original is frozen, a way back is prepared, and the server using the volume is locked. After this approval, the next step is the switch.
3. The switch worked (also called G4)
After the switch, the volume was checked on the new storage and works.

The first two approvals are given together (the button "Approve before switching"), then you press "Release" to allow the switch. The third is the button "Approve the result". The person who started the move cannot approve: another person must.

      Helper servers

      Do you need this? Only if some volumes have long-lived snapshots (the "Staged copy" group in the scan). Those volumes are copied by a small program, the data mover, running on a Linux migration host. A Cinder host creates the new volume record. One server can do both. If you have no such volumes, you can skip this page.
      Step 1. OpenMove's public key

      Add this line to ~/.ssh/authorized_keys of the login user on each helper server. It is the only credential OpenMove keeps.

      
      
      
    
      
    
      
      Step 2. Set up a new helper server from here
      
      Give OpenMove the server's address and the administrator login. OpenMove logs in once with the password, installs its own key, prepares the server, sets up the storage paths you describe, registers it and checks it. The password is used for this setup only. It is not saved, not written to the journal or a log, and not left on the server. You can run the setup again. Every step looks first and changes only what differs.
      
      
      
        
        
        
        
        
        
        
      
      
      
      2a. Check the server's identity
      
      
      The password goes only to a server whose identity a person has compared. Read the key, compare the fingerprint with the server's console or its administrator, and type what you checked.
      
      
      
        
        
        
      
      
      
      
      
      2b. Storage paths
      
      
      
        
        
        
      
      
      
      "Read the host" logs in with the password once and changes nothing. It lists the initiator name, the Fibre Channel port names, the network interfaces, the sessions and the multipath devices, so that you can fill in the form and register the names on the arrays. It needs the identity check of step 2a.
      
      
      
      
      
      
      2c. Run
      
      
      
        
        
        
        
        
        
      
      
      
      
    
      
    
      
      Step 3. Read and change a helper server that is already set up
      
      After the setup a helper server is managed through OpenMove only. OpenMove connects with its key, sends its own checked scripts through the control program on the host and applies the storage configuration: portals, target names, interfaces, addresses, MTU, session settings, CHAP, Fibre Channel ports and multipath. The management interface is never changed. The CHAP secret is asked again each time and is not kept.

      Support
      
    
      If something goes wrong, a support bundle holds everything needed to find the fault without access to this site: the history, every step with its result, every call to the cloud and to the servers, the log, and what each server reports about itself. OpenMove also writes one by itself when it stops or meets an unexpected error. Send the bundle to whoever supports you.
